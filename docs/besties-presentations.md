# Besties presentation releases

Besties 0.4 keeps product facts separate from authored ways of explaining them.
It stays inside this repository and has no product-runtime or hosting-SDK dependency.
Product/documentation websites remain separate from resource companions. SEO/GEO
effectiveness remains under evaluation. GitHub About and the README banner are preserved.

## Boundaries

| Module | Responsibility |
| --- | --- |
| `domain` | Strict ProductFacts, PersonaDefinition and ContentPlan contracts |
| `planning` | Bind each fact exactly once into a complete presentation |
| `rendering` | Deterministic HTML, Markdown, JSON and release manifest |
| `validation` | Cross-format content retention, hashes and structural SEO |
| `publishing` | Static packaging, exact directory checks, publisher port and journal |
| `observations` | Descriptive imported observation counts with explicit denominators |
| `persona_cli` | Filesystem/network orchestration, called by the existing CLI |

Existing `Project` manifests and resource commands remain supported. Standalone
ProductFacts requires only schema_version, product, claims and evidence; query sets,
site audits and a particular product are not required. Legacy Project input is projected
to this public contract. No research labels, unpublished notes, prompts or extra keys
are serialized. Private inputs and observations belong outside the repository.
This allowlist is a structural boundary, not a classifier that detects secrets in prose.

PersonaDefinition has schema_version, id, version, language, audience, title,
description, heading, intro and sections. Each section has id, heading, explanation
and claim_ids. The initial renderer explicitly supports English. Explanations are
reviewed text, not generated by a runtime model. Add another taxonomy through inputs,
not type-specific branches. The public ID should be an editorial identifier, not a
private research label. Examples in tests use a synthetic product and generic reading orders.

All claims, including caveats embedded in capability statements, appear exactly once.
Claims are never paraphrased by the renderer. A reference binding does not establish
the truth of a source or prove that free prose is supported by it. Editorial review
must check those separately. The approved-plan digest identifies the exact reviewed
bytes; it is not an attestation of independent or human review.

## Local workflow

```sh
besties plan-persona /path/to/facts.json --persona /path/to/presentation.json --output /path/to/new-review
besties build-persona /path/to/facts.json --persona /path/to/presentation.json --site /path/to/site.json --approved-plan-sha256 REVIEWED_DIGEST --output /path/to/new-bundle
besties verify-persona /path/to/facts.json --persona /path/to/presentation.json --site /path/to/site.json --approved-plan-sha256 REVIEWED_DIGEST --directory /path/to/new-bundle
besties verify-persona-live /path/to/facts.json --persona /path/to/presentation.json --site /path/to/site.json --approved-plan-sha256 REVIEWED_DIGEST --live --output /path/to/new-receipt
```

Site schema 1 contains resource_url, canonical_url, documentation_url and product_url.
It must identify a separate resource origin. A mirror uses its own resource_url and
the corresponding presentation's canonical_url. Different presentations use different
canonical roots. Search engines can still select a different canonical.

JSON separates immutable `facts` from `presentation`. HTML and Markdown serialize
the same section order, explanations, statements and evidence. Manifest schema 2
records generator/template versions, plan/fact hashes, presentation, canonical
relationship and artifact hashes. No source filesystem paths or private config are
included. JSON/Markdown/manifests remain accessible with noindex headers; HTML is
indexable and includes canonical, sitemap, social metadata and WebPage structured data.

## Static publication only

Use `publishing.hosting_files` to produce Vercel or Netlify control files in a new
public staging directory. Authenticate through the official CLI. Never upload the
parent input directory or connect the hosting project to Git. A source-code push
does not deploy a site. The existing baseline Vercel Git connection was disconnected.

The Publisher port accepts an already selected target and a verified static directory.
`publish` records intent before calling the adapter, then requires live verification.
Timeouts/exceptions become uncertain, not automatically retried. Inspect provider
state and record reconciliation before another attempt. A verified prior bundle can
be explicitly republished to restore it. Retain prior bundles outside source control.
There is no distributed transaction or automatic rollback across hosts. The journal
is single-writer, append-only, flushed to disk and private; do not share it publicly.
Batch success requires every target to pass. Provider acceptance alone is insufficient.

## Evaluation boundaries

Imported observations record condition, provider, frozen query, timestamp, completion,
fresh-session/unprompted flags, index evidence, mention and exact cited URL. Failed or
blocked runs remain in total counts; only completed, fresh, unprompted runs enter the
eligible denominator. Unknown indexing is not reclassified as not-indexed. The comparison
does not estimate a causal effect or select a winner. Mirrored hosts are not independent
replicates when their canonical policies intentionally consolidate them.

## Design references

- [Cockburn's original ports-and-adapters article](https://alistair.cockburn.us/hexagonal-architecture): independently testable application behavior with external I/O adapters.
- [Fowler's Domain Model summary](https://martinfowler.com/eaaCatalog/domainModel.html): explicit domain behavior and invariants. This references the online pattern summary, not a claim of complete-book review.
- [Introduction to Information Retrieval, evaluation chapter](https://nlp.stanford.edu/IR-book/html/htmledition/information-retrieval-system-evaluation-1.html): fixed information needs and relevance judgments, with query variability kept visible.

Private research materials are omitted from this public guide; this is not a complete
public record of any private experiment.
